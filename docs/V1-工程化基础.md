# V1：工程化基础

## 本阶段解决的问题

### 1. 统一接口响应

`ApiResponse<T>`保证所有接口都返回相同结构：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

- `code`：业务状态码，`0`表示成功。
- `message`：给调用方的结果说明。
- `data`：接口真正返回的数据。

HTTP状态码仍表达请求级别的结果，例如参数错误返回HTTP 400，系统异常返回HTTP 500。

### 2. 统一错误码

`ErrorCode`定义错误码必须具有的内容，`CommonErrorCode`保存所有模块都可能使用的公共错误。

以后用户、节目和订单模块可以分别增加自己的错误码枚举，而不需要修改公共接口。

### 3. 业务异常与全局异常处理

业务代码遇到无法继续执行的情况时抛出`BusinessException`。`GlobalExceptionHandler`负责把异常转换为标准响应，Controller不需要到处编写`try-catch`。

未知异常只向客户端返回“系统异常”，详细堆栈保留在服务端日志中，避免泄露内部实现。

### 4. 参数校验

`HelloRequest`使用`@NotBlank`和`@Size`声明参数规则，Controller通过`@Valid`触发校验。

参数校验失败后的调用流程：

```text
POST /api/hello
    ↓
Spring MVC读取JSON
    ↓
@Valid校验HelloRequest
    ↓
校验失败，抛出MethodArgumentNotValidException
    ↓
GlobalExceptionHandler捕获异常
    ↓
返回HTTP 400和统一错误响应
```
