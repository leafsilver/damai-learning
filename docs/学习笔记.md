# damai-learning 学习笔记

> 这份笔记随项目演进持续更新。代码由学习者按照步骤执行，笔记由 Codex 负责整理和维护。

## 学习目标

通过一个简化版票务项目，形成阅读和理解 Java 后端工程的能力：

- 看懂 Spring Boot 项目的目录和启动过程
- 能够沿着 Controller、Service、Mapper 追踪业务调用链
- 理解常见工程化基础设施为什么存在
- 理解 MySQL、Redis、消息队列和 Elasticsearch 在真实业务中的作用
- 最终能够阅读普通版大麦的核心代码，并逐步理解大麦 Pro 的高级设计

## 学习方式

每个知识点按照固定顺序学习：

```text
提出问题
→ 理解原始实现的缺陷
→ 获得本次需要添加的代码
→ 学习者亲自修改和运行
→ 观察运行结果
→ 解释完整调用流程
→ 对照大麦项目
→ 提交 Git 记录
```

没有经过学习者亲自运行验证的内容，不记录为“已完成”。

## 项目演进记录

### V0：最小可运行的 Spring Boot 项目

#### 当前代码包含

- Java 17
- Maven
- Spring Boot 3.5.16
- Spring Web
- 应用启动类
- 一个 GET 测试接口
- 基础自动化测试

#### Maven项目坐标

```xml
<groupId>com.damai.learning</groupId>
<artifactId>damai-learning</artifactId>
<version>0.0.1-SNAPSHOT</version>
```

- `groupId`：项目或组织的标识
- `artifactId`：当前项目名称
- `version`：项目版本，`SNAPSHOT`表示开发中的版本

#### 核心依赖

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

`spring-boot-starter-web`主要提供：

- Spring MVC
- JSON序列化
- 内置Tomcat
- Web应用常用依赖

#### 启动入口

```java
@SpringBootApplication
public class DamaiLearningApplication {

    public static void main(String[] args) {
        SpringApplication.run(DamaiLearningApplication.class, args);
    }
}
```

`@SpringBootApplication`启用自动配置和组件扫描。启动类放在`com.damai.learning`包下，因此能够扫描其子包中的Controller等组件。

#### 第一个接口

```java
@RestController
@RequestMapping("/api")
public class HelloController {

    @GetMapping("/hello")
    public String hello() {
        return "damai-learning is running";
    }
}
```

最终接口地址：

```text
GET /api/hello
```

调用流程：

```text
HTTP请求
→ 内置Tomcat
→ Spring MVC
→ HelloController.hello()
→ HTTP响应
```

#### 本阶段验证命令

运行测试：

```powershell
mvn test
```

启动应用：

```powershell
mvn spring-boot:run
```

在另一个PowerShell终端调用接口：

```powershell
Invoke-RestMethod -Uri 'http://localhost:8080/api/hello'
```

预期响应：

```text
damai-learning is running
```

#### 学习者验证状态

- `mvn test`：已验证
- 应用启动：已验证
- `/api/hello`接口：已验证

## 常用注解速查

这部分只记录项目中已经实际出现过的注解。后续每引入一个新注解，就继续补充。

### `@SpringBootApplication`

使用位置：Spring Boot启动类。

```java
@SpringBootApplication
public class DamaiLearningApplication {
}
```

主要作用：

- 标记Spring Boot应用入口
- 启用自动配置
- 扫描启动类所在包及其子包中的Spring组件

记忆：**启动、自动配置、组件扫描。**

常见问题：启动类位置过深，可能导致其他包中的Controller或Service无法被扫描。

### `@RestController`

使用位置：提供HTTP接口的类。

```java
@RestController
public class HelloController {
}
```

作用：让Spring管理当前类，并把方法返回值直接写入HTTP响应。

可以理解为：

```text
@Controller + @ResponseBody
```

记忆：**这个类提供JSON或文本接口。**

### `@RequestMapping`

使用位置：Controller类或方法。

```java
@RequestMapping("/api")
```

作用：设置请求路径。放在类上时，作为当前类所有接口的公共路径前缀。

记忆：**公共路径。**

### `@GetMapping`

使用位置：Controller方法。

```java
@GetMapping("/hello")
```

作用：把HTTP GET请求映射到Java方法。

当前项目的完整路径：

```text
@RequestMapping("/api") + @GetMapping("/hello")
= GET /api/hello
```

记忆：**查询通常使用GET。**

### `@SpringBootTest`

使用位置：测试类。

```java
@SpringBootTest
class DamaiLearningApplicationTests {
}
```

作用：测试时启动完整的Spring应用上下文，适合验证Spring配置和组件能否正确加载。

记忆：**带着Spring容器运行测试。**

### `@AutoConfigureMockMvc`

使用位置：Spring Boot测试类。

作用：自动配置`MockMvc`，使测试代码可以在不真正启动网络端口的情况下模拟HTTP请求。

记忆：**测试Controller接口。**

### `@Autowired`

使用位置：字段、构造方法或Setter方法。

```java
@Autowired
private MockMvc mockMvc;
```

作用：从Spring容器中找到匹配的对象并注入。

当前代码用它注入测试需要的`MockMvc`。

记忆：**从Spring容器拿对象。**

工程代码中更推荐构造方法注入；这里暂时保留简单写法，后面学习Service时再比较不同注入方式。

### `@Test`

使用位置：JUnit测试方法。

```java
@Test
void contextLoads() {
}
```

作用：标记一个可以由JUnit执行的测试方法。

注意：它属于JUnit，不属于Spring。

记忆：**这是一个自动化测试。**

## Git提交规范速查

项目使用“英文类型前缀 + 中文说明”的提交格式：

```text
<类型>: <本次修改的中文说明>
```

例如：

```text
feat: 添加统一响应结果
```

### 常用提交类型

| 前缀 | 使用场景 | 示例 |
| --- | --- | --- |
| `feat` | 新增功能 | `feat: 添加用户注册功能` |
| `fix` | 修复问题 | `fix: 修复库存重复扣减问题` |
| `docs` | 修改文档 | `docs: 补充Redis学习笔记` |
| `refactor` | 重构代码，但不改变原有功能 | `refactor: 重构订单创建流程` |
| `test` | 增加或修改测试 | `test: 添加节目查询接口测试` |
| `chore` | 构建、配置、依赖等杂项 | `chore: 调整Maven构建配置` |

### 如何选择前缀

```text
增加了用户能够使用的新能力？
→ feat

修正了错误行为？
→ fix

只修改说明文档或学习笔记？
→ docs

代码结构发生变化，但对外行为不变？
→ refactor

只增加或修改测试？
→ test

依赖、构建、工具配置发生变化？
→ chore
```

### 提交说明的要求

- 使用中文描述具体做了什么
- 尽量只描述一个主题
- 避免使用“修改代码”“更新项目”等模糊说明
- 提交前先确认测试通过
- 不在提交说明中包含密码、Token等敏感信息

推荐：

```text
feat: 添加节目分页查询接口
```

不推荐：

```text
更新代码
修改一下
fix bug
```

### 相关命令

```powershell
git add .
git commit -m "feat: 添加统一响应结果"
git push
```

- `git add .`：将当前项目的变更放入暂存区
- `git commit -m "..."`：将暂存区内容保存为一次本地提交
- `git push`：将本地提交推送到远程仓库

## V1：统一响应与接口文档

### 统一响应Result

原始接口直接返回字符串，不同接口很容易形成不同的响应结构。项目增加`Result<T>`，把响应统一为：

```json
{
  "code": 0,
  "message": "success",
  "data": "damai-learning is running"
}
```

三个字段的职责：

- `code`：业务状态码，当前约定`0`表示成功
- `message`：本次请求的结果说明
- `data`：真正的业务数据，类型由泛型`T`决定

常见类型：

```java
Result<String>
Result<UserVO>
Result<List<UserVO>>
```

当前只实现了成功响应。失败响应、业务错误码和全局异常处理将在下一阶段加入。

### Result的关键设计

```java
private Result(int code, String message, T data)
```

构造方法使用`private`，限制其他代码随意创建不同格式的响应。

```java
public static <T> Result<T> success(T data)
```

通过静态工厂方法统一创建成功响应。

Getter不仅供Java代码读取字段，也方便Jackson把对象转换成JSON。

### 接口自动生成的真正条件

项目引入Springdoc后，它会扫描Spring MVC接口并生成OpenAPI描述。

真正定义接口的是Spring MVC注解：

- `@RestController`
- `@RequestMapping`
- `@GetMapping`
- 后续还会使用`@PostMapping`、`@PutMapping`、`@DeleteMapping`

`@Tag`和`@Operation`不是自动发现接口的必要条件。删除它们以后，接口仍然会生成，只是文档名称和说明不够友好。

### OpenAPI地址

```text
http://localhost:8080/v3/api-docs
```

返回给程序读取的JSON接口定义，Apifox导入这个地址。

```text
http://localhost:8080/swagger-ui.html
```

返回给人查看和调试的Swagger UI网页。这个网页内部仍然需要读取`/v3/api-docs`。

### Apifox同步方式

- 手动导入：接口发生变化后重新导入`/v3/api-docs`
- 定时导入：在项目设置中绑定OpenAPI数据源
- 使用本地URL同步时，Spring Boot应用必须正在运行

### 当前测试策略

- 普通CRUD和展示接口：主要使用Apifox手动验证
- 应用基础状态：保留`contextLoads`测试
- 登录、下单、库存、支付和消息消费：编写自动化测试
- 不要求每个小改动都同时执行手动调用和自动化测试

### `@Tag`

来源：Swagger/OpenAPI注解。

```java
@Tag(name = "基础接口")
```

作用：给一组接口设置文档分组名称。

记忆：**给Controller分类。**

注意：它只改善接口文档，不负责把类注册为Spring组件，也不负责发现接口。

### `@Operation`

来源：Swagger/OpenAPI注解。

```java
@Operation(summary = "检查服务是否运行")
```

作用：设置单个接口在文档中的名称和说明。

记忆：**说明这个接口做什么。**

注意：它只提供文档信息，真正映射GET请求的是`@GetMapping`。
